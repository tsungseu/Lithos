# 新增项目与知识沉淀使用说明

适用角色：开发工程师、技术负责人。原则：项目保存事实，知识库保存提炼成果；一个成果只维护一个正式位置。

一、日常启动

完整解压便携包，双击“启动工作台.cmd”，浏览器打开 http://127.0.0.1:8765 。已内置运行时，不需安装Python。服务仅监听本机。关闭服务窗口后网页不再提供功能，再次运行启动文件即可恢复；历史草稿保存在工具的data目录。资料位置与端口见config.json，详细配置见同目录“离线使用与配置.md”。分发包默认使用包内workspace，本机安装版继续使用D盘。

二、新增项目

配置页面：点击左侧“配置”，或访问 /app/settings。外观支持浅色、深色、跟随系统和三档字号；模型设置按供应商统一保存Base URL、API Key、模型对象和默认模型。数据页可修改资料根目录与端口：目标须为含两类资料目录的已有父目录，保存到config.json，关闭服务并重新启动后生效，不移动任何资料。应用页显示版本、草稿位置及离线能力。浏览器配置不随ZIP分发。

页面左侧点击“＋”，选择自动驾驶、机器人或其他项目，输入名称。省略编号时自动续接当前领域的最大编号；也可明确输入“09_项目名称”。同名项目不会覆盖，已有编号不会重排。

新建目录仅包含：
01_计划与需求
02_方案与设计
03_开发与验证
04_问题与改进
05_交付与验收

01目录自动生成“项目说明.md”，先填写目标、范围、稳定需求编号、验收标准及负责人。其余文件按实际工作需要添加，不自动铺设空子目录，不创建README、软链接或快捷方式。

三、工作过程中如何放资料

• 计划与需求：项目说明、会议决定、需求与变更；需求编号沿用Jira等已有编号。
• 方案与设计：设计说明、接口约定、评审结论及备选方案取舍。
• 开发与验证：直接放文档或完整工程包，例如“采集工具_v1.2”；测试材料最多再用一层“测试报告”。不增加“版本/历史资料/资源包”的外部套层，不拆开代码、配置和依赖。
• 问题与改进：维护一份问题台账，记录Bug编号、发现版本、复现步骤、运行记录、根因、修复版本与复测证据。
• 交付与验收：按实际版本或阶段放交付清单、使用限制和验收结果。

版本用Git commit/tag或明确版本名标识。本地未提交修改要对应补丁或可追溯快照。不要用“最终版2”代替版本关系。
运行确有需要时，使用“日期_序号_任务”命名；记录输入数据、模型、配置、日志位置及结论。较大的日志仍留在真实运行位置，把关键片段和解释整理到项目文档供模型读取。
可复用空白字段见工具包内“项目记录模板.md”。本机既有模板仍位于 D:\07_工具与资产\01_文档模板\项目记录模板.md 。

四、何时值得沉淀

一个Bug完成复测、一项方案完成评审、一轮试验有可解释结果、一个阶段完成交付时，整理一次。只选能支撑结论的少量材料，不需要每次全项目上传。

推荐最小证据组合：
1. 背景或需求：为什么要做、原来的限制。
2. 方法或方案：采取了什么措施、哪些替代方案被排除。
3. 验证或复盘：效果如何、证据在哪、失败条件是什么。

五、通过页面调用大模型

无需模型时：选择项目证据后点击人工草稿入口，在本地填写结论、证据与适用边界，保存并审核入库。未选择证据也可记录想法，但不能直接入库；应先准备证据，再新建绑定来源的草稿。该流程不调用外部接口。使用已部署的本机兼容模型服务也可离线提炼，工具包不内置模型权重。

1. 选择项目，再勾选1—12份资料。支持MD、TXT、DOCX和文字型PDF；代码仓库、依赖、运行日志目录默认不遍历。Excel、PPT、扫描PDF请先整理成文字摘录；不支持的内容不会被悄悄当作已读取。
2. 填写本次沉淀目标，点击“预览待发送资料”，在当前项目页内展开，不弹窗或跳页。每份正文不超过3万字符、合计不超过8万字符；超出时会提示调整，不静默截断。提取DOCX主要保留正文文字，复杂图表、公式、图片须另行解释；PDF文字提取也可能丢失排版，务必检查预览。
3. 在预览中检查实际正文、来源编号和系统规则。页面到此只做本地读取。
4. 在“配置 → 模型设置”添加供应商，填写Base URL、API Key和模型ID。项目空间只选择供应商、模型ID与effort。DeepSeek默认基础地址为 https://api.deepseek.com/v1；通义预设为中国内地DashScope基础地址。自定义地址不包含 /chat/completions。
5. 点击“发送所选资料并生成草稿”才会将预览正文与Key发给所选模型服务商，可能产生账户费用。供应商、Key和模型信息持久化在当前设备的应用浏览器数据中，不写入项目文件、知识库、草稿或服务日志，也不通过工作台同步到其他设备。
6. 成功的模型结果自动保存到本机草稿，可编辑并点击“保存草稿”，也可从“历史草稿”恢复。失败不会自动重复调用，也不会入库。

六、审核与入库

逐项检查：结论是否真有来源编号[S1]等；指标是否来自实际报告；草稿和建议是否误写成已验证；是否保留失败场景、适用边界、未解决问题；是否值得跨项目复用。所有关键结论必须保留证据编号。

选择知识专题并填写标题，勾选审核确认后入库：
• 行业专属结论：03_技术知识库/01_自动驾驶 或 02_机器人。
• 跨领域开发、部署、性能与排障：03_技术知识库/03_工程实践。
• 采集处理、数据质量及闭环：03_技术知识库/04_数据与闭环。
• 原始论文、阅读笔记仍放06_论文与调研；开源仓库与资源包仍放03_技术知识库/05_开源项目，不能把它们当作沉淀结论。

工作台只写入现有知识专题的实体Markdown文档，文件名带日期时间与标识，禁止覆盖同名历史成果。来源路径、提取时SHA-256、项目和模型信息自动附在文后；来源发生变化时会拒绝入库，需重新提取。审核入库并不等于工程验证通过。

七、查找、修订与维护

“知识库”页按真实目录浏览整个03_技术知识库，包含05_开源项目及深层子目录。无关键词时显示当前目录的文件和文件夹；输入关键词后递归检索当前目录，所有格式按文件名和路径匹配，MD、TXT、DOCX和文字PDF还会检索可提取正文。每页100项，可翻页；点击文件夹进入，使用上一级返回。普通文件可预览或下载原件；不支持的格式只显示信息，不假装已读取正文。检索跳过隐藏项和依赖缓存，最多扫描2万项或12秒，达到上限会明确提示，应缩小到具体目录后重试。正文提取上限12MiB、20万字符，限制和提取异常会显示提示。新入库文档会立即进入该页面检索。此次Web页面动态读取目录；之前的“资料索引.xlsx”是静态快照，不会因本工具操作而自动更新。
修订已有知识时，先明确沿用的来源和新增证据，以新的草稿产生修订稿，并在正文写明替代哪一篇；本版本不自动合并或覆盖知识文档。已发布的草稿不能再次发布。
项目事实仍由项目维护，知识文档只保留必要的结论和来源引用。冻结版本或交付证据不随意改名；历史来源以后被迁移，需要同步修正文档的来源路径。

八、DLP与已有资料

DLP保持原路径及现有布局，本工具仅读取允许的文档目录，不移动、重命名或整理DLP工程。不会创建软链接或快捷方式，也不会执行删除旧副本操作。
上轮迁移旧副本的递归删除仍受执行规则拦截，与本工作台独立；不能因为建立知识文档就删除唯一项目原件。

九、本版本范围

这是单机工作台，不是多用户审批系统。支持兼容接口的非流式chat/completions文本回复，调用超时约120秒；不支持自动扫描全盘、自动训练模型、OCR、自动执行模型指令。模型结论始终需要人工判断。接口密钥由使用者保存在当前设备的应用浏览器数据中；交付测试使用模拟兼容接口，不代表已经使用你的真实账户完成联网调用。

十、知识图谱

知识库点击“知识图谱”切换视图。默认当前目录三层，可选1—4层；每次最多250节点，包含目录和可预览文档，未加入的文件仍可从目录浏览查看。实线表示目录归属，虚线表示当前范围内可唯一解析的Markdown链接或[[双链]]，不根据内容猜测语义关系，也不把代码块示例当作引用。点击目录后选择“展开此目录图谱”，进入局部范围；上一级返回。点击文档可在图谱旁阅读，并查看引用/被引用文档。搜索框定位当前图谱内节点，滚轮缩放、拖动画布，支持放大、缩小及适配画布。根目录图谱中没有虚线可能是资料尚未写链接或目标不在当前层数范围，并非知识丢失。

十一、多供应商配置与路由

模型设置支持新增、选用、编辑和删除多家供应商。每家可保存API Key，批量添加模型，并编辑模型ID、显示名、上下文窗口及默认模型。项目空间可快速切换供应商、模型ID和effort，选择会成为下次默认值。删除供应商会同时删除本机保存的Key，不删除项目或草稿。旧版单接口配置会迁移为“原有模型配置”。

点击“测试”后会使用该供应商在本机保存的Key；确认发送才调用接口，发送内容仅固定连接测试短句，可能产生服务商费用。不会发送项目资料或保存草稿。当前协议为OpenAI Chat Completions，支持云端HTTPS及本机HTTP兼容服务。

导航地址：工作台/app、项目/app/projects、知识库/app/knowledge、指南/app/guide、配置/app/settings。支持直接打开、刷新以及浏览器前进后退。配置入口位于主侧栏底部。此版本参考指定Vue项目的分组、供应商管理、导航与校验思路，不引入其股票行情、钱包、桌面托盘、自动更新等不属于本工具的功能。

十二、项目页内生成

资料预览与生成区域直接在项目页展开，不显示模型配置或Key输入。项目标题下方只保留供应商、模型ID与effort切换；资料正文可展开核对，主动点击生成后才发送。
API Key随供应商持久化在当前设备对应站点或桌面应用的浏览器数据中。桌面版数据位于应用数据目录的browser分支；浏览器版由浏览器管理。Key不会写入项目、知识库、草稿、config.json或服务日志。它不是系统凭据库加密项，能够访问当前Windows账户和浏览器数据的人可能读取，因此不应在共享账户保存生产Key。


## 项目资料原件预览（2.3）
在项目资料列表点击“预览”，可在当前项目中阅读原件，选择“展开阅读”放大。无需安装 Office，全部组件随离线包提供，原件不上传第三方。Word（DOCX）支持正文、表格、常见图片及分页；复杂域、EMF/WMF图片等以本机 Office 为准。Excel（XLSX/XLS）支持切换工作表，每表显示已用区域前200行、40列，公式仅显示已保存的计算结果，不呈现图表，不执行宏；Excel目前仅供阅读，不能勾选为模型证据。PDF可逐页阅读、翻页和缩放；加密或特殊字体文件可能需要本机阅读器。MD/TXT可查看文字。旧DOC及PPT/PPTX尚未支持。单文件12MiB，Office压缩包展开大小上限64MiB。
“预览待发送资料”仍展示提炼实际使用的文字内容，只有点击发送生成才调用配置的模型接口。
