# Lithos 记忆平台使用说明

## 本地沉淀

左侧“记忆中心”管理来源、任务、候选、知识与 Skill。项目右侧的“生成可复用知识候选”会使用勾选资料创建任务，不直接写入正式知识库。

在记忆中心选择“启用当前模型后台处理”，将当前供应商、模型、effort 及 Key 保存为后台配置。Windows 使用当前用户的 DPAPI 加密，不上传 Key 至团队。后台配置是当时的快照，切换供应商后需再次点击此按钮更新。

启用后监测整个工作区的支持文件，稳定两分钟并合并十分钟变化后自动排队。知识库、应用数据、隐藏、依赖、构建和原始日志目录不递归提炼。默认每天20任务、50调用、20万输入及4万输出token，预算保守按UTF-8字节上界及输出限额预留，不代表供应商实际账单。设置位于记忆中心“检索设置”。

“暂停后台处理”停止取新任务；已经发出的请求可能完成。单个任务可暂停、取消或重试。任务保留原始工作区及目标知识库，即使切换目录也不改投新目录。

## 候选与审核

候选支持新增、更新、重复、冲突。打开候选核对来源全文片段、引用位置和差异；更新前检查目标版本。锁定资产不允许更新；来源变化时需要重新生成。未经审核内容不参与 Agent 默认召回。

外部 Agent 提交和旧文档导入没有自动补造来源，必须勾选“待验证知识”才能入库。原文引句校验只能证明引用确实出现，不能代替人工检查结论是否被证据支持。

“导入已有知识待复核”生成待审核候选，不覆盖旧文档。“知识与 Skill”可锁定、反馈、打开资产；Skill 可导出为 SKILL.md，不执行脚本。

## 检索

默认中文单字/双字组合及英文词语 BM25 排序。可在“检索设置”指定当前供应商的 embedding 模型，显式建立向量索引；启用后以 RRF 合并排名。缺失向量或接口失败回退本地检索。默认只召回最多8片段和保守6000token预算内内容。

已审核资产是召回范围，现有普通文档需先导入复核。外部修改的资产会停止召回并标记待复核。

## Agent 接入

创建客户端时必须填写项目标识和允许访问的资产 ID。令牌仅显示一次，可随时撤销。默认允许代理留存会话30天，可在创建时关闭。只收集经过该代理的内容。

独立网关与桌面读取同一个 WORKBENCH_HOME 配置，启动时固定工作区：

```text
python -m backend.memory_gateway --port 8770
```

便携包使用内置 runtime/python.exe memory_gateway.py --port 8770。Agent 配置 Base URL 为 http://127.0.0.1:8770/v1，API Key 为创建的 Agent 令牌。上游接口与 Key 使用本机后台模型配置。

HTTP MCP 地址为 http://127.0.0.1:8770/mcp，使用 Bearer 令牌。也支持 stdio：

```text
python -m backend.memory_gateway --stdio
```

stdio 从 LITHOS_AGENT_TOKEN 环境变量读取令牌。支持 initialize、tools/list、tools/call，工具为 memory_search、memory_read、project_context、memory_submit、memory_feedback。没有审核、发布或删除工具。

代理支持 /v1/chat/completions 与 /v1/responses 的文本、SSE及工具调用透传。未知参数和多模态输入明确拒绝。检索超时不注入记忆。更换工作区时需为独立网关重启到对应配置，旧客户端不会自动获得新工作区权限。

## 团队服务

团队部署独立于桌面，在 team 目录配置环境变量 LITHOS_DB_PASSWORD 和 LITHOS_BOOTSTRAP_TOKEN，执行 docker compose up --build。默认只暴露本机8430端口，远程使用需要配置HTTPS反向代理。

使用一次性 /api/v1/bootstrap 初始化团队管理员；随后 /api/v1/login 获取一天有效的登录令牌，管理员通过 /api/v1/users 建立编辑者或阅读者。API交互说明位于服务 /docs。部署后应移除引导令牌。

记忆中心“团队共享”支持登录，或填入已有登录令牌。预览已审核资产并明确发布后才上传；默认不上传证据片段。当前API支持显式选择原文证据摘录，界面默认只发布正文。原始文件、原始会话及模型Key不会同步。

管理员与资产所有者可撤销共享。团队Agent使用独立、可撤销的资产白名单凭据。所有读取先过滤团队和授权范围，未授权资产返回不存在。正式团队环境需先完成PostgreSQL集成验收。

团队 `/api/v1/search` 支持中文词法 BM25，`/api/v1/agent/search` 的 POST 接口使用同样的检索逻辑并先限制资产授权。可由授权编辑者上传已发布版本的向量至 `/api/v1/assets/{id}/vector`（model、vector、revision），检索时提供相同模型的查询向量以启用 pgvector 与 RRF。正文更新会清除旧向量。团队服务不会自行读取本机模型 Key，也不会自动调用 embedding；当前桌面团队召回默认使用词法检索。

发布绑定预览时的资产版本和正文，修改文件或更换资产后必须重新预览。已失效或外部修改的资产需重新审核。会话到期会清除任务、候选及资产证据中的原始会话文本，并将相关资产标记待复核；已人工审核形成的知识正文仍保留。

候选审核页支持修改正文后保存候选，之后仍需核对证据并正式入库。任务列表显示已经提取的片段数；提取完成不代表模型保留了每个事实，长资料仍需人工核对。后台工作进程与入库操作具有进程级文件锁，避免两个本机服务同时处理或提交同一工作区。

## 运行与验证边界

桌面功能继续离线可用。云端模型、远程embedding及团队服务需要对应网络；本机模型可以离线生成。

团队服务当前环境未运行真实PostgreSQL/pgvector（未安装Docker）。30组样例为合成确定性检查，不是实际模型质量提升评测。真实模型的引用正确率、审核修改率、召回率及token对比需要在指定模型和脱敏资料上补充。
